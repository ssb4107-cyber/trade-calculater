# 재점검 P2 수정 및 Supabase 전환 보고서

작업 범위: 2026-10-06 재점검 P2 9건 전체와 사용자가 추가 승인한 Supabase 로그인·서버 저장 전환.

## P2 수정

| 항목 | 문제 | 수정 및 검증 |
|---|---|---|
| R01 | 여러 창에서 서로 다른 종목을 고정하면 한 설정이 사라짐 | 최신 설정을 잠금 안에서 읽고 각 변경을 적용. 서버에서는 버전 비교 후 충돌 시 재적용. 두 창의 고정·개별 상태 저장 10회 검증. |
| R02 | 계산 기록 동시 저장 시 기록 하나가 사라짐 | 계산 기록도 저장 트랜잭션 사용. 잠금 안에서 고유 ID를 발급하며 최신 기록 8개 유지. 두 창 동시 저장 10회 검증. |
| R03 | 저장 대기 중 취소·재열기한 입력 창의 새 입력이 사라짐 | 입력 창 열림 회차를 구분하고 해당 회차에만 저장 후 초기화/닫기 적용. 포지션·부분매도·종목 설정의 새 입력 보존 검증. 종목 추가 창에도 동일 보호 적용. |
| R04 | 손상된 자료의 중복 ID 때문에 다른 포지션·거래까지 삭제됨 | 중복/잘못된 ID를 안정적으로 분리하고 수정 전 원본 백업. 선택한 포지션/거래만 삭제되는지 검증. |
| R05 | 알 수 없는 매도 유형·보유 초과 매도가 정상 자료처럼 계산됨 | 의미상 잘못된 거래가 있는 포지션을 격리하고 원본 보관. 서버에도 거래 유형·수량·중복 ID 검증 적용. |
| R06 | 계산 기록 ID가 숫자 문자열이면 삭제되지 않음 | 읽을 때 숫자로 통일하고 중복 ID 분리. 기존 문자열 ID 기록 삭제 검증. |
| R07 | 정렬 중 다른 창의 상태 갱신이 드래그를 취소함 | 드래그 중 목록 노드 유지, 이동 순서 저장 완료 후 목록 갱신. 실제 마우스 이동과 다른 창의 상태 저장이 겹쳐도 순서 유지 검증. |
| R08 | 다른 창에서 늦게 끝난 오래된 시세가 최신 시세를 덮어씀 | 저장된 공용 요청 토큰으로 최신 요청만 반영. 시세 캐시에도 시간 역행 방지. 서로 다른 창의 늦은 응답 검증. |
| R09 | 낮은 화면 높이에서 포트폴리오 상세 영역에 접근할 수 없음 | 낮은 높이의 좁은 화면에서 포트폴리오 전체 세로 스크롤 허용. 600×300, 667×375, 683×384의 메뉴 접힘/펼침 6가지 상태에서 포지션 입력 접근 검증. |

고정·수동 설정을 계속 보존하며 미설정 종목의 최근 사용 우선 노출을 유지합니다. 미완료 거래의 입력값을 다른 창의 갱신으로 초기화하지 않습니다. 기존 설정의 다크모드·메뉴 접힘도 여러 창 사이에 반영하도록 보완했습니다.

## Supabase 구현

이메일/비밀번호 로그인, 로그인 유지, 로그아웃, 사용자별 서버 저장, 원본 백업을 포함한 최초 자료 이전, 서버 시세 함수, 호출 제한을 구현했습니다. 브라우저에는 프로젝트 공개 URL/publishable key만 사용하고 Finnhub 키는 서버 비밀 값으로 등록하도록 구성했습니다.

실제 사용자 자료에 접근하거나 변경하지 않고 통제된 브라우저 환경과 임시 PostgreSQL에서 검증했습니다. 모든 데이터베이스 마이그레이션은 새 프로젝트에 적용할 수 있는 파일로 보관했습니다.

## 검증과 적용 상태

- 수량/복구 단위 검증: 기존 18개와 아주 작은 수량·숫자 합계 넘침의 손상 자료 검증 1개, 총 19개.
- 시세 서버 인증/출처/요청 제한/캐시/비밀 값 비노출 검증: 5개.
- 재점검 P2 브라우저 검증: 17개. 고정·계산 기록 동시 저장은 각 10회 반복. 재열기뿐 아니라 같은 입력 창에서 저장 중 작성한 새 내용도 보존.
- 기존 브라우저 검증: 41개 통과. 15가지 화면 크기, 수량·손익·시세·입력·저장 실패·검색과 메뉴 접근 포함.
- 실제 PostgreSQL 엔진: 익명 접근 차단, 계정 간 자료·백업 분리, 직접 수정 차단, 버전 충돌, 중복 요청, 거래 검증, 호출 제한과 원자적 이전 검증.
- 공식 Supabase SDK 브라우저 연동: 로그인 실패/성공, 로그인 복원, 다른 컴퓨터의 저장 충돌, 로컬 업무 자료 미기록, 실패 시 입력 보존, 응답 단절 후 중복 방지, 로그아웃/계정 전환 검증.

**P2 9건의 코드 수정은 완료했으나 운영 사이트 반영은 대기 중입니다.** Supabase 설치와 계정 연결 완료 답변을 받았지만 이번 실행의 관리 도구 목록에는 프로젝트 기능이 노출되지 않았습니다. 대체 브라우저 경로도 실행 환경 오류로 시작하지 못했습니다. 실제 무료 프로젝트 생성, 마이그레이션 적용, 이용자 계정 발급, 서버 비밀 값 등록, 실제 서버 검증과 운영 배포가 남아 있습니다. `backendConfig.js`가 비어 있는 상태로 서버 전환이 완료됐다고 판단하지 않습니다.

공개된 기존 Finnhub 키를 복원하는 조치는 자동 승인 검토에서 재노출 위험을 이유로 거절되었습니다. 해당 복원을 수행하지 않았습니다. 키를 제거한 변경 전체를 PR로 올리고, 실제 서버 연결 후 운영 배포하도록 구성합니다. 기존 노출 키의 폐기·교체가 필요하므로 이전 P1 F01은 공급자 키 교체 확인 전까지 완결 처리하지 않습니다.

적용 순서는 [Supabase-setup.md](Supabase-setup.md)에 정리했습니다.
